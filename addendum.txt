# Design-Only Redesign Requirements

## Purpose

This requirements file is intended to be **consumed by a local CLI-based tool** to guide a **visual redesign only** of the existing application.

**No functional changes are permitted.**

The tool must treat all existing behavior, logic, data flow, routes, APIs, and integrations as **immutable**.

---

## Project Context

* Project root: `/var/www/html`
* An existing requirements file already defines application functionality
* The current UI uses a **zombie-themed design**, which is to be replaced

This document **supplements** existing requirements and applies **only to look-and-feel**.

---

## Scope Constraints (Hard Rules)

The redesign MUST:

* Preserve all existing functionality
* Preserve component structure and page layout hierarchy
* Preserve routes, API calls, and data models
* Preserve form fields, tables, and interactions

The redesign MUST NOT:

* Add new features
* Remove features
* Rename routes or components
* Change validation, submission, or data handling logic
* Modify backend or frontend business logic

If a change is not purely visual, it is **out of scope**.

---

## Redesign Objective

Replace the current zombie-themed UI with a **clean, professional design** suitable for client-facing demonstrations.

The visual style should communicate:

* Technical competence
* Reliability
* Intentional design

---

## Visual Theme Requirements

### Color Scheme

* Primary background color: **Black** or near-black
* Primary text color: **Green** (readable, not fluorescent)
* Secondary text: Muted green or green-gray variants
* Accent usage should be minimal and consistent

White backgrounds should not be used.

---

### Typography

* Use a clean, modern, professional typeface
* Monospace or technical-feeling fonts are acceptable but not required
* Typography should emphasize clarity and hierarchy
  n* Avoid novelty or horror-themed fonts

---

### Styling Tone

* Minimalist
* Professional
* Purpose-driven

Avoid:

* Cartoonish visuals
* Horror motifs
* Decorative imagery unrelated to function
* Excessive animations

---

## Component Styling Guidance

The CLI tool may adjust **visual styling only** for:

* Page backgrounds
* Text colors
* Font families and sizes
* Spacing and alignment
* Borders, shadows, and hover states

All components must remain functionally identical.

---

## Accessibility Considerations

* Maintain sufficient contrast between text and background
* Ensure readability on mobile and desktop
* Preserve visible focus states for interactive elements

---

## Success Criteria

The redesign is considered successful if:

* The application looks professional and client-ready
* The black background / green text theme is consistently applied
* All existing functionality works exactly as before
* No functional regressions are introduced

---

## Interpretation Rules for CLI Tool

When ambiguity exists:

* Prefer **no change** over speculative change
* Prefer conservative, minimal styling updates
* Never infer new features or interactions

This document should be treated as **design guidance only**, not a functional specification.
